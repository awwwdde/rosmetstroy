# Деплой на платформу `<slug>.awwwdde.art`

Проект соответствует контракту гостя платформы (GUEST.md): один `Dockerfile` в корне,
приложение слушает `0.0.0.0:8080`, `GET /healthz` отвечает 200, в образе есть `curl`,
всё состояние хранится в PostgreSQL.

## Что внутри образа

```
платформа (TLS) → :8080 Caddy ─┬─ /api/v1/*, /media/* → FastAPI 127.0.0.1:8000
                               ├─ /api/revalidate     → 404 (вызывается только изнутри)
                               └─ всё остальное       → Next.js 127.0.0.1:3000
```

Запуском управляет `deploy/platform/start.sh`:

1. переводит переменные платформы в переменные приложения (см. таблицу ниже);
2. `alembic upgrade head` — миграции;
3. `python -m app.cli bootstrap` — стартовый контент, если база пустая, и первый
   администратор, если пользователей ещё нет;
4. запускает FastAPI и Next.js, ждёт их готовности и только потом поднимает Caddy на
   8080, поэтому `/healthz` отвечает 200, когда работает всё приложение;
5. если любой процесс упал, контейнер завершается и платформа его перезапускает.

## Переменные окружения

Платформа сама даёт `DATABASE_URL`, `PUBLIC_SITE_URL`, `SECRET_KEY` — их задавать не нужно.
`DATABASE_URL` вида `postgresql://…` приложение само переводит на драйвер asyncpg.

В панели (карточка стенда → `.env`) **перед первым деплоем** добавьте:

| Переменная | Зачем |
|---|---|
| `ADMIN_EMAIL` | e-mail первого администратора |
| `ADMIN_PASSWORD` | его пароль, не короче 10 символов |

Администратор создаётся один раз — пока в базе нет ни одного пользователя. Пароль,
сменённый потом в админке, при передеплое не перезаписывается. Если переменные забыли,
добавьте их и передеплойте.

Необязательные:

| Переменная | Зачем |
|---|---|
| `NOTIFY_EMAILS`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | письма о новых заявках |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления о заявках в Telegram |
| `STORAGE_BACKEND=s3` + `S3_*` | хранить файлы в S3 вместо PostgreSQL (см. ниже) |
| `PUBLIC_SITE_URL` | свой домен вместо `<slug>.awwwdde.art` — для канонических ссылок и sitemap |

Выводятся сами и обычно не задаются: `SITE_URL`, `CORS_ORIGINS` (= `PUBLIC_SITE_URL`),
`COOKIE_SECURE` (true для https), `REVALIDATE_SECRET` (HMAC от `SECRET_KEY`).

## Файлы

Диск контейнера стирается при каждом деплое, поэтому по умолчанию (`STORAGE_BACKEND=db`)
загруженные в медиатеку изображения и вложения заявок хранятся в таблице `stored_files`.
Публичные файлы отдаются по `/media/…` с вечным кэшем, вложения заявок — только через
админку. Для сайта компании этого достаточно; если файлов станет много (гигабайты),
подключите S3-совместимое хранилище: `STORAGE_BACKEND=s3`, `S3_BUCKET`, `S3_ENDPOINT_URL`,
`S3_REGION`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_PUBLIC_URL`. Файлы, загруженные до
переключения, останутся в базе и перестанут отдаваться: переключайтесь до наполнения сайта.

Платформа не бэкапит гостевые базы. Так как в базе лежат и файлы, делайте `pg_dump`
сами (например, с сервера: `docker exec <slug>_db pg_dump -U <slug> <slug> > backup.sql`).

## Проверка перед деплоем

```bash
docker build -t rosmetstroy-check .
```

```bash
docker run --rm -p 8080:8080 -e DATABASE_URL=postgresql://rosmetstroy:rosmetstroy@host.docker.internal:5432/rosmetstroy -e SECRET_KEY=local-check-secret-key-0123456789 -e ADMIN_EMAIL=admin@example.com -e ADMIN_PASSWORD=change-me-please rosmetstroy-check
```

```bash
curl http://localhost:8080/healthz
```

## Ограничения

- Счётчики защиты от перебора (rate limit) живут в памяти процесса и сбрасываются при деплое.
- Фоновых воркеров нет: уведомления о заявках отправляются в фоне того же процесса FastAPI.
